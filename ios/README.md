# 콘텐츠 스튜디오 iPhone 앱

`ContentStudio.xcodeproj`는 iOS 17 이상을 대상으로 하는 독립 실행 SwiftUI 앱입니다. 일상 사진 영상 편집, 음악·폰트 첨부, 자막 위치 변경, iPhone 내 H.264 MP4 제작, 파일 공유, 사진 기반 AI 자막, `.studio` 프로젝트 교환을 포함합니다. Mac은 카드뉴스와 일상 영상을 모두 만들고, iPhone은 일상 영상에 집중합니다. Mac 앱이나 Mac 서버가 없어도 영상 제작 기능을 사용할 수 있습니다. Mac에서 실행하는 OpenCode·로컬 FreeLLMAPI는 iPhone 내부에서 실행되지 않으며, 해당 모델은 iPhone이 접속할 수 있는 HTTPS 서버가 있을 때만 사용합니다.

## 일상 영상 만들기

1. 홈의 **새 일상 영상**을 누르고 사진을 1~10장 선택합니다. 큰 사진은 자동 축소하고, 선택 순서대로 장면을 만듭니다.
2. **다음**에서 제목·분위기·설명·말투를 입력한 뒤 직접 자막 또는 AI 자막으로 시작합니다.
3. 편집 화면에서 사진 썸네일을 선택하고 하단 **사진 / 자막 / 효과 / 음악 / 썸네일** 도구를 엽니다. 도구가 열린 상태에서도 미리보기를 볼 수 있습니다. 편집 내용은 자동 저장합니다.
4. 재생·시간 슬라이더로 장면 순서를 확인하고, 확대 버튼으로 전체 화면 미리보기를 봅니다.
5. **완성하고 저장하기 → MP4 만들기**로 제작한 뒤 파일 앱에 저장하거나 공유합니다.

Mac 일상 편집과 같은 설정을 제공합니다: 화면 채우기/사진 전체 표시, 가로·세로 위치, 장면 길이(2~30초·0.5초 단위), 장면 순서, 자막·폰트 9종과 직접 첨부, 자막 크기·위치·박스 스타일, 사진 움직임 5종, 컷/페이드 전환, 분위기별 BGM 2~3곡 추천·총 11곡과 직접 첨부, 음악 미리듣기·음량·시작 구간. 참고 채널의 Kevin MacLeod CC BY 4.0 곡 8개는 게시 문안 공유 시 음악 출처를 포함합니다. 오리지널 CC0 곡 3개는 출처 표기 없이 사용할 수 있습니다. 사진과 자막은 장면 순서를 바꿀 때 함께 이동합니다. MP4 재생은 무음 모드에서도 소리를 출력합니다.

사진 또는 자막 도구의 **AI 자막 추천**은 선택한 축소 사진 1장과 분위기·설명·말투를 연결한 AI 업체로 보냅니다. 해당 장면의 자막만 변경하며 다른 자막·게시 문안·효과·음악을 보존합니다. 전체 제안은 영상 메뉴의 **모든 사진 자막 제안**을 사용합니다. 직접 편집에는 API 키가 필요하지 않습니다. 이미지 입력을 지원하는 모델을 사용하세요. 완성 영상은 재생 전에도 사진을 표시하며 사진 파일을 읽을 수 없으면 다시 선택할 수 있도록 안내합니다.

2026-10-11: 연결된 iPhone 15 Plus에 BGM 업데이트 **빌드 5**를 기존 앱 식별자로 설치하고 실행했습니다. 실제 기기 검증 31개를 통과했으며 기존 프로젝트 파일은 업데이트 전후 동일했습니다. 기기 등록 이후에도 앱 변경사항은 새 빌드 설치를 통해 반영됩니다.

이후 가져오기·보내기 안내를 **PC 버전 Content Studio** 명칭으로 통일한 **빌드 6**도 같은 iPhone 15 Plus에 설치·실행했으며, 기존 프로젝트 파일 보존을 확인했습니다.

## iPhone에 설치하는 방법

1. 이 Mac에 설치된 Xcode를 실행합니다. 다른 Mac이라면 Mac App Store에서 Xcode를 설치하고 초기 구성을 마칩니다.
2. Xcode에서 `ios/ContentStudio.xcodeproj`를 엽니다.
3. **Xcode → Settings → Accounts**에서 본인의 Apple 계정으로 로그인합니다. 비밀번호는 Xcode에만 입력합니다.
4. **ContentStudio Target → Signing & Capabilities**에서 **Automatically manage signing**을 켜고 본인의 Apple 개발 팀을 고릅니다. 현재 프로젝트는 개인 설치용 `com.leesungmin.contentstudio.personal`로 설정되어 있습니다. 다른 계정으로 설치할 때는 고유한 Bundle Identifier를 사용하세요.
5. iPhone을 Mac에 연결하고 iPhone에서 이 컴퓨터를 신뢰합니다. 개발자 모드가 요구되면 켭니다.
6. Xcode 상단에서 실제 iPhone을 대상으로 고른 뒤 **Run**을 누릅니다. Xcode가 빌드·서명하고 iPhone에 앱을 설치합니다.
7. 처음 실행할 때 신뢰 오류가 나오면 iPhone의 **설정 → 일반 → VPN 및 기기 관리 → 개발자 앱**에서 본인 계정을 신뢰합니다. 개발자 모드는 **설정 → 개인정보 보호 및 보안 → 개발자 모드**에서 켭니다.

현재 설치 프로파일은 **2026년 10월 18일 오전 4시 19분(한국 시간)**에 만료됩니다. 이후 실행이 안 되면 같은 앱 식별자로 다시 빌드·설치해야 합니다. 기존 프로젝트를 보존하려면 앱을 먼저 삭제하지 마세요.

다른 사용자에게 다운로드 링크를 제공하려면 Apple Developer Program 계정으로 앱을 서명하고 TestFlight에 업로드해야 합니다. TestFlight 링크가 준비되기 전까지는 앱을 직접 내려받아 설치할 수 없습니다. 시뮬레이터용 `.app`이나 앱 소스는 iPhone 설치 파일이 아닙니다.

## Mac과 주고받기

Mac의 일상 영상 편집 화면에서 **iPhone용 프로젝트**를 누르고 `.studio` 파일을 AirDrop이나 파일 앱으로 보냅니다. iPhone 홈의 **앱 설정 → PC 버전에서 가져오기**로 엽니다. 역방향은 iPhone **영상 메뉴 → 게시 문안 · PC 버전으로 보내기 → 프로젝트 파일 만들기**를 사용하고, Mac의 **내 콘텐츠 → iPhone 프로젝트 가져오기**에서 엽니다.

사진·음악·폰트·장면 순서·자막 설정·움직임·전환·분위기·설명·말투·음악 시작 구간을 함께 옮깁니다. API 키와 MP4는 프로젝트 파일에 넣지 않으며 자동 동기화는 아닙니다.

iPhone에서 새 카드뉴스 제작이나 카드 프로젝트 가져오기는 제공하지 않습니다. 기존에 저장한 카드 프로젝트는 그대로 보관하고, 홈의 **앱 설정 → 이전 카드 프로젝트를 PC 버전으로 보내기**에서 내보낼 수 있습니다.

### Mac 인증정보를 개발용 iPhone 앱으로 이전

USB 개발 설치에서는 Debug 빌드의 `--import-mac-credentials` 실행 인자로
앱 비공개 `tmp/mac-credentials.json`을 한 번 읽을 수 있습니다.
가져온 키는 기기 잠금 해제 시에만 접근 가능한 기기 전용 Keychain에 저장하고,
전송 파일은 즉시 삭제합니다. `tmp/mac-credentials-receipt.json`에는 키 값 없이
저장 검증 결과만 남습니다. 이 기능은 Release 빌드에 포함되지 않습니다.
키 파일을 저장소, 앱 번들, 로그에 포함하지 마세요.

AI 제공자를 전환하면 제공자별 모델명과 서버 주소가 유지됩니다.
Mac의 `127.0.0.1` FreeLLMAPI 주소는 iPhone에서 사용할 수 없으므로,
iPhone에서 접속 가능한 HTTPS 서버 주소가 별도로 필요합니다.

### 개발 검증

Debug 개발 설치의 `--verify-rendering`은 별도 임시 프로젝트로 제공 음악 11곡, 분위기별 추천 수, 출처가 포함된 게시 문안, 오디오 트랙, 일상 MP4, 음악 시작 구간, 사진 축소, 장면 순서 저장, 프로젝트 교환, 사진 AI 요청 형식, 움직임 5종과 제작 취소를 검사합니다. 기존 사용자 프로젝트는 수정하지 않습니다. `--preview-daily-home`, `--preview-daily-create`, `--preview-daily-editor`는 임시 예제 저장소를 이용한 화면 검증 인자입니다. Release 빌드에는 포함되지 않습니다.

## TestFlight 배포 상태

2026-10-11 현재 Release 아카이브는 생성했지만 TestFlight 업로드는 완료되지 않았습니다. Xcode에 연결된 팀이 무료 Personal Team이고 App Store Connect 계정 연결이 없어 App Store 배포 서명을 만들 수 없었습니다. TestFlight 배포를 계속하려면 활성 유료 개발자 팀을 Xcode에 연결해야 합니다.

[다른 사람에게 iPhone 앱을 설치·배포하는 방법](../docs/IOS_INSTALL_GUIDE.md)

사진별 **AI 자막 추천**과 사진 미리보기 보완을 포함한 **빌드 8**을 iPhone 15 Plus에 설치했습니다. 선택한 사진 1장만 보내는 AI 요청, 다른 장면 보존, 축소 미리보기의 사진 표시 등을 포함한 실제 기기 검사 41개를 통과했고 기존 프로젝트 파일 보존을 확인했습니다.

**썸네일** 도구 또는 완성·저장 화면에서 장면을 선택하면 대표 이미지로 사용합니다. 장면 ID로 선택을 저장하여 재정렬해도 같은 장면을 유지하고, 선택한 장면이 삭제되면 첫 장면을 사용합니다. MP4에 표지 이미지를 넣고 썸네일 JPG도 함께 저장·공유합니다. 이전 프로젝트는 첫 장면을 기본 썸네일로 사용합니다.

썸네일 선택을 포함한 **빌드 9**를 iPhone 15 Plus에 설치했습니다. 실제 기기 검사 47개와 프로젝트 보존 확인을 통과했습니다. Mac도 같은 기능을 응용 프로그램 폴더의 최신 앱에 반영했습니다.

자막 도구의 폰트 미리보기는 크기 슬라이더와 함께 바뀝니다. 선택한 크기는 모든 장면의 미리보기·완성 MP4에 적용됩니다. 사진·썸네일은 화면 갱신 중에 동기 생성하지 않고 필요한 해상도로 준비하며, MP4 제작은 프레임별 임시 메모리를 해제하고 인코더 버퍼를 재사용합니다. 제작 중에는 저장 화면을 닫을 수 없고 **제작 중단**으로 취소할 수 있습니다.

DEBUG의 `--verify-rendering`은 기본·번들 폰트 각각의 24/96 크기 프레임, 실제 인코딩한 MP4의 글씨 크기, 크기 저장도 검사합니다. `--verify-export-ui`는 기존 일상 프로젝트의 사진을 임시 프로젝트로 복사해 10장·30초 영상의 저장 화면과 실제 MP4 제작을 실행합니다. 원본 프로젝트는 변경하지 않으며 `tmp/export-ui-receipt.json`에 저장 결과·화면 응답 검사를 기록합니다.

2026-10-11: 저장 화면 응답 지연·제작 중 임시 메모리 누적과 고정 크기의 폰트 미리보기를 수정한 **빌드 10**을 iPhone 15 Plus에 설치했습니다. 실제 기기에서 사진 10장·30초 MP4/음악/썸네일 제작과 화면 응답 검사 8개, 기본·번들 9종 폰트의 크기 및 기존 기능 검사 61개를 모두 통과했습니다. 기존 프로젝트 2개는 업데이트 전후 동일합니다. 시뮬레이터에서도 같은 검사를 통과했습니다.

빌드 10의 검사는 파일 생성·음악·글씨 크기를 확인했지만, 기본 페이드 전환이 적용된 MP4의 사진 픽셀 검사를 빠뜨렸습니다. 실제 저장 파일에서 사진이 검게 덮이는 문제를 재현한 뒤 **빌드 11**에서 수정했습니다. 투명 검정 덧씌우기에 사용하는 그리기 방식을 `.copy`에서 `.normal`로 바꾸고, 영상 전체의 첫·마지막 프레임은 사진을 유지합니다. 이전 출력은 다시 제작해야 하며 편집 화면에서 재제작을 안내합니다.

2026-10-11: 빌드 11을 iPhone 15 Plus에 설치했습니다. 실기기와 시뮬레이터에서 첫·마지막 프레임 및 장면별 사진 픽셀 검사를 포함한 **65개 검사**, 사진 10장·30초 저장 화면의 응답과 실제 출력 사진을 확인하는 **20개 검사**를 통과했습니다. iPhone에 저장되어 있던 검은 일상 영상도 원본 프로젝트로 다시 제작하고, 새 MP4의 5개 장면과 첫·마지막 화면 및 JPG를 디코딩해 확인했습니다. 사진·자막·음악·썸네일 선택 등 편집 내용은 보존했습니다.

DEBUG의 `--repair-saved-videos`는 실제 저장소의 이전 버전 일상 MP4를 다시 제작합니다. 디코딩한 사진이 원본 렌더링과 일치하고 제작 중 원본 편집 내용이 바뀌지 않은 경우에만 새 출력 경로를 저장합니다. 검증 결과는 `tmp/repair-video-receipt.json`에 기록하며 기존 출력 파일은 삭제하지 않습니다. Release 빌드에는 포함되지 않습니다.
