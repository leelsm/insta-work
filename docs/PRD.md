# Instagram Content Studio — PRD

작성일: 2026-10-04 · 버전: 0.2 · 상태: 구현 전 검토 초안

초기 구현이 시작됐다. 현재 동작·검증·남은 항목은 [구현 현황](IMPLEMENTATION_STATUS.md)에 별도로 기록한다. 이 PRD는 목표 범위를 나타내며 모든 기능의 구현 완료를 뜻하지 않는다.

## 1. 목표

실행파일 하나로 로컬 웹 기반 관리 화면을 열고, 콘텐츠 후보 수집 → 카드뉴스 기획 → 자막·음성 포함 영상 제작 → 검토 → 지정 인스타그램 계정 게시까지 관리한다. 프로그램 창을 닫으면 로컬 서버와 소유한 작업 프로세스가 종료된다.

첫 버전부터 Windows와 macOS를 동등하게 지원한다. 같은 코드베이스와 웹 UI를 사용하며 Windows는 EXE, macOS는 앱 번들로 각각 배포한다. 하나의 바이너리가 두 OS에서 실행되는 방식은 아니며 사용자는 자신의 OS용 앱을 설치한 뒤 동일한 흐름으로 사용한다. macOS Apple Silicon·Intel 및 Windows x64를 배포 검증 대상으로 한다. Linux는 현재 범위에 포함하지 않는다.

사용자 확정: 크로스플랫폼 지원, Phase 1 수동 게시, Phase 2 자동 게시. 수동 게시란 사용자가 최종 검토 후 앱의 게시 버튼을 눌러 API 업로드를 시작하는 방식이다. MP4를 내보내 인스타그램에서 직접 업로드하는 방법도 제공한다. 예약 게시 역시 Phase 2로 분리한다.

## 2. 사용자 요구와 제안 기본값

| 항목 | 요구/설계 |
| --- | --- |
| 실행 | Windows EXE / macOS 앱 실행 시 서비스 시작 및 동일한 웹 UI 표시 |
| 포트 | 기본 `127.0.0.1:80`; 권한 또는 점유 문제 발생 시 원인 표시, 사용자가 대체 포트 선택 가능 |
| 종료 | 앱의 마지막 관리 창 닫기 또는 종료 메뉴 실행 시 서비스·워커·렌더러 종료; Phase 2는 스케줄러도 종료 |
| 계정 | 인스타그램 계정 정보와 API 연결 정보 등록; 여러 계정 저장, 작업당 대상 1개 선택 |
| 수집 | 네이버 뉴스 키워드 검색 우선; 실제 인기뉴스 및 블라인드 인기글은 허가·연동 가능성 확인 후 확장 |
| 제작 | 카드 이미지와 세로 영상, 영상 내 자막, 게시글 본문·해시태그 생성 |

| 운영 | Phase 1은 사용자 조작으로만 게시. Phase 2 예약 작업은 앱 실행 중에만 수행 |

## 3. 외부 서비스 제약과 제품 반영

### 인스타그램

Meta 공식 API를 사용하며 지원되는 프로페셔널 계정(비즈니스/크리에이터)을 대상으로 한다. 아이디·비밀번호 자동 로그인 방식은 사용하지 않는다. 계정 별칭, Instagram 사용자 ID, 인증 상태, 권한, 토큰 만료 상태를 관리한다. Instagram Login 경로를 우선 검증하며 실제 OAuth 리디렉션 구성, 앱 모드·검수·권한은 연동 실험에서 확정한다.

영상 전송은 실제 지원 경로를 검증한 뒤 결정한다. 로컬 파일을 직접 전송하는 지원 방식이 가능하면 우선 사용하고, 공개 미디어 URL이 필요하면 임시 HTTPS 저장소의 제한된 수명 URL을 제공한다. `localhost` 주소를 외부 서비스 다운로드 URL로 전달하지 않는다. 앱 종료 후에도 이미 Meta에 전달된 게시 요청은 완료될 수 있으며 게시를 자동 취소할 수 있다고 표시하지 않는다.

근거: [Meta 공식 Instagram API 문서 컬렉션](https://www.postman.com/meta/workspace/instagram/documentation/23987686-9386f468-7714-490f-9bfc-9442db5c8f00). 실제 API 버전, 권한, 업로드 방식, 미디어 규격과 게시 한도는 개발 시 다시 확인한다.

### 네이버 뉴스

공식 뉴스 검색 API는 키워드 검색과 정확도순/날짜순을 제공한다. 검색 결과의 제목·요약·원문 링크·발행 시각을 저장한다. 검색 요약은 기사 전문이 아니므로 근거가 부족하면 원문 제공 또는 사용 가능한 원문 소스 연결을 요청한다.

‘인기뉴스 순위’와 ‘검색 후보 추천 점수’를 분리한다. MVP는 최신성·키워드 일치·중복 여부로 후보를 추천하며 이를 네이버 실제 인기순위라고 표시하지 않는다. 실제 인기순위 수집은 허용된 공급 경로, 조회 시각, 순위 기준을 확인한 별도 어댑터로 구현한다.

근거: [네이버 뉴스 검색 API](https://developers.naver.com/docs/serviceapi/search/news/news.md).

### 블라인드와 콘텐츠 이용

블라인드 약관은 명시적 허가 없는 수집·복제 등을 제한한다. 자동 인기글 수집은 허가된 데이터 제공 경로를 확보한 뒤 구현한다. MVP는 운영자가 이용 권한을 확보한 텍스트·자료를 입력하는 기능을 제공한다. URL 입력만으로 원문 사용 권한이 확보된 것으로 처리하지 않는다.

원문, 사진, 음악, 폰트 등은 사용 가능한 자료로 구성한다. 출처 표시만으로 재사용 권한이 해결된다고 가정하지 않는다. 출처 URL·시각·사용 권한 메모를 콘텐츠에 기록한다. 블라인드 글의 개인·회사 식별 정보는 검토 과정에서 제거하거나 비식별화할 수 있어야 한다.

근거: [Blind 이용약관](https://kr.teamblind.com/setting/term_and_privacy?lang=en).

## 4. 핵심 사용자 흐름

1. 앱 실행 → 포트 확인 → 서비스 준비 → 관리 창 표시.
2. 설정에서 네이버, 생성 모델, 선택적 TTS, 인스타그램 인증 연결을 등록하고 연결 테스트.
3. 검색어·기간·제외어 설정 → 후보 검색 → 제목·요약·출처 확인 → 제작할 후보 선택.
4. 대상 계정·템플릿·길이·말투·음성을 지정해 초안 생성.
5. 카드별 제목·본문·음성 대본·출처와 게시글 문안을 편집.
6. 영상 렌더링 → 미리보기 → 자막·내용·계정 확인 → 현재 버전 승인.
7. 사용자가 게시 버튼 클릭 → 결과·게시 ID·가능한 게시 링크 확인. 또는 MP4 내보내기 후 인스타그램에서 직접 업로드.
8. 앱 종료 → 신규 작업 차단 → 진행 중 작업 체크포인트 저장 → 소유 프로세스 종료.

## 5. 기능 요구사항

### F01. 실행과 종료

- 서버는 기본적으로 루프백에만 바인딩하며 외부 네트워크에 노출하지 않는다.
- 단일 인스턴스 실행. 두 번째 실행은 기존 창으로 연결한다.
- 포트 80 충돌 시 다른 프로세스를 종료하지 않고 충돌 안내 및 대체 포트 선택 화면을 제공한다.
- macOS 등에서 낮은 포트 권한 문제가 발생하면 안내한다. 전체 앱을 관리자 권한으로 상시 실행하는 방식을 기본으로 삼지 않는다.
- 일반 브라우저 탭 닫기는 종료 신호로 신뢰할 수 없어 기본 UI는 앱 소유 웹뷰 창으로 제공한다.
- 종료 목표 시간 10초. 미완료 렌더링은 중단 상태로 기록하고 앱이 생성한 자식 프로세스만 정리한다.
- 종료 시 데이터는 보존한다. 이미 외부로 전송된 게시 요청은 결과 미확인 상태로 저장한다.
- 앱 중단·재실행 시 작업을 복구하되 게시를 자동 반복하지 않는다.

### F02. 설정과 계정

- 계정 별칭, 프로필 정보, 인증 상태, 만료 상태, 기본 템플릿·문체 등록.
- 키 입력값 마스킹, 변경·삭제·연결 테스트 제공. 비밀값은 OS 보안 저장소에 저장하고 DB에는 참조만 저장한다.
- 네이버 Client ID/Secret, LLM 공급자·모델·키, 선택적 TTS 공급자·음성 설정.
- 미디어 저장소가 필요한 경우 저장소 설정 및 외부 접근 가능 여부 테스트.
- 토큰 만료·권한 부족은 해당 계정 게시를 중지하고 재연결 안내.

### F03. 수집과 선정

- 키워드, 제외 키워드, 기간, 최대 후보 수 설정. 기본 후보 수 20개.
- 소스, 제목, 요약, URL, 발행 시각, 수집 시각, 지원되는 경우 실제 순위 표시.
- URL 정규화·본문 해시 기반 중복 제거; 유사 제목은 묶어 운영자가 선택.
- 입력 텍스트 및 사용 가능한 파일을 통한 수동 콘텐츠 등록.
- 원문 확보 실패는 상태로 표시하고 근거가 없는 내용 생성은 차단.
- 공급자 호출 한도·429 응답에 따른 대기, 제한된 재시도, 오류 안내.

### F04. 카드뉴스 기획

- 기본 5~7장: 도입, 핵심 정보, 맥락, 마무리·출처. 카드 수는 편집 가능.
- 카드 제목·본문, 내레이션 대본, 장면 길이, 출처 참조를 구조화된 JSON으로 생성.
- 한국어 기본, 계정별 말투·금칙어·브랜드 색상 설정.
- 사실 주장마다 제공 자료에 연결된 출처를 유지하며 추정·의견과 사실을 구분.
- 기사나 게시글 내부의 지시문을 모델 실행 지시로 취급하지 않는다.
- 생성 결과는 스키마 검증 후 저장. 카드별 수정·재생성·순서 변경 지원.
- 승인 이후 문안·장면·계정·음성이 바뀌면 승인을 해제하고 필요 시 재렌더링.

### F05. 영상과 자막

- 제안 기본 출력: 1080×1920, 9:16, MP4, H.264/AAC, 30fps, 30~60초. 게시 전 실제 API 규격 검증.
- 카드 PNG도 별도 저장하며 MVP의 인스타그램 게시 대상은 릴스 영상.
- 라이선스 확인된 한글 폰트, 두 가지 기본 템플릿, 로고 및 색상 설정.
- 텍스트 넘침 검출, 줄바꿈·폰트 크기 조절, 인스타그램 UI를 고려한 안전 영역 제공.
- 음성 사용 시 TTS 타임스탬프 또는 정렬 결과에 맞춘 자막; 음성 미사용 시 장면 길이에 맞춘 자막.
- 자막은 영상에 삽입하고 SRT를 함께 내보낸다. 자막 편집과 타이밍 수정 제공.
- 음악은 선택적이며 새 프로젝트에 기본 BGM을 선택합니다. 사용 권한이 확인된 곡만 제공하고 음악 없음도 선택할 수 있습니다.
- 진행률, 취소, 실패 이유, 결과 파일 경로, 재렌더링 제공.

### F06. 검토와 게시

- 미리보기에서 최종 영상, 게시 계정, 문안, 해시태그, 출처 확인.
- 승인한 콘텐츠 버전만 게시 가능. MVP는 자동 생성 직후 자동 게시하지 않는다.
- Phase 1은 사용자가 게시 버튼을 눌러 즉시 게시하거나 MP4를 내보낸다. 예약 UI·스케줄러는 Phase 1에서 제공하지 않는다.
- Phase 2는 예약 게시를 추가한다. 화면은 Asia/Seoul 기본, 저장은 UTC. 종료 중 지난 예약은 재실행 시 미실행으로 표시하고 사용자가 처리 방식을 선택한다.
- 게시 전 인증·파일 규격·승인 버전·중복 여부 검사.
- 업로드, 컨테이너 생성, 처리 상태 확인, 게시 요청, 게시 결과 확인을 각각 기록.
- 타임아웃으로 결과가 불명확하면 ‘확인 필요’로 표시. 원격 상태 확인 없이 게시 요청을 반복하지 않는다.
- 계정+콘텐츠 버전의 게시 작업에 고유 키를 두고 동일 작업의 동시 게시 차단.
- 앱이 종료되기 전 외부로 전달된 요청은 재실행 후 상태 조회로 조정한다.

### F07. 작업 기록과 자동화

- 단계·진행률·시작/종료 시각·오류 코드·재시도 횟수·게시 ID 기록.
- 재시도는 실패 단계부터 수행하며 완료된 생성·렌더 결과를 재사용한다.
- Phase 2 자동 운영 규칙: 계정, 소스, 키워드, 실행 주기, 하루 게시 상한, 검토 정책, 비용 상한.
- 자동 모드에는 중단 버튼, 중복 방지, 인증 장애 시 중지, 운영 기록을 제공한다.
- 상시 자동 운영은 앱 실행 유지가 필요하다. 종료 후에도 운영하려면 별도의 상시 서버 제품 범위가 필요하다.

| 작업 이력 | 작업 상세, 오류, 재시도, 게시 결과, 결과 미확인 |

## 7. 권장 아키텍처

웹 UI(React + TypeScript + Vite)를 앱 소유 웹뷰(pywebview)에 표시하고, Python FastAPI가 정적 파일·로컬 API를 제공한다. Python 작업 워커와 FFmpeg가 제작을 수행하며 SQLite에 상태를 저장한다. 배포는 PyInstaller 기반으로 OS별 검증한다. 이 구성은 웹 UI를 유지하면서 영상 작업과 실행파일 수명주기를 한 앱에서 관리하기 위한 제안이다.

- Launcher: 인스턴스 잠금, 포트 선택, 서버 상태 확인, 웹뷰 수명주기, 종료 처리.
- API: 계정·설정·소스·콘텐츠·작업·게시 엔드포인트.
- Worker: 영속 작업 큐를 조회하고 한 번에 기본 렌더 1개 처리; 원격 호출 제한 적용.
- Adapters: 네이버, 수동 자료, LLM, TTS, Meta, 선택적 저장소를 인터페이스로 분리.
- Renderer: 카드 레이아웃 → 이미지 → 자막·오디오 타임라인 → FFmpeg.
- Storage: SQLite, OS별 사용자 데이터 폴더의 프로젝트·미디어·로그, OS 보안 저장소.
- Scheduler (Phase 2): DB의 예정 작업을 앱 실행 중 조회. 작업 임대와 고유 제약으로 중복 실행 방지. Phase 1에서는 실행하지 않는다.
- 플랫폼 계층: 데이터 경로, 보안 저장소, 웹뷰, 프로세스 종료 처리를 OS별 구현으로 분리한다. Windows Credential Manager와 macOS Keychain을 사용하고, 웹뷰 런타임 요구사항을 설치 단계에서 처리한다.
- 인증 배포: 개인 자체 Meta 앱은 개인 자격 증명을 OS 보안 저장소에 보관한다. 공통 Meta 앱을 사용하는 일반 배포는 App Secret을 실행파일에 넣지 않고 HTTPS 인증 중계에서 관리한다. 로컬 UI와 OAuth 콜백 주소를 분리하며 최종 콜백 구성은 0단계에서 검증한다.
- 배포: OS·CPU별 네이티브 빌드와 실행/종료 검증. Windows 코드 서명 및 macOS 서명·공증을 배포 준비에 포함한다. 서명 자격 증명은 별도 확보하며 서명 완료 전에는 완료로 표시하지 않는다.

데이터는 설치 폴더에 저장하지 않는다. 패키지에는 실행에 필요한 웹 파일·FFmpeg·폰트를 포함하며 라이선스와 재배포 조건을 확인한다. 실제 설치 크기와 웹뷰 런타임 의존성은 패키징 실험에서 확정한다.

## 8. 데이터와 상태

Phase 1 테이블: accounts, credential_refs, source_configs, source_items, projects, content_versions, scenes, assets, jobs, publication_attempts, audit_events. schedules는 Phase 2에서 추가한다.

- 모든 프로젝트는 대상 계정, 출처 스냅샷, 생성 설정, 콘텐츠 버전을 참조한다.
- 미디어는 파일 해시, 경로, 규격, 생성 버전, 사용 권한 정보를 기록한다.
- 제작 상태: DRAFT → GENERATING → EDITABLE → RENDERING → REVIEW_READY → APPROVED.
- 게시 상태: READY → UPLOADING → PROCESSING → PUBLISHING → PUBLISHED.
- 단계별 예외: FAILED, CANCELLED, INTERRUPTED, NEEDS_RECONCILIATION. Phase 2에 SCHEDULED, MISSED 추가.
- 제작/게시 상태는 별도 관리한다. 게시 결과 미확인 상태를 단순 실패로 바꾸지 않는다.
- Phase 2에서 삭제는 관련 예약을 먼저 해제하고 원격 게시물 삭제와 로컬 자료 삭제를 구분한다.

## 9. 비기능 요구사항

- 보안: 루프백 바인딩, 세션 인증, Origin 검증, CSRF 방어, 비밀값 로그 제외, 파일 경로 검증.
- 외부 URL 처리: 내부 IP·루프백·파일 URL 차단, 리디렉션마다 재검증, 다운로드 용량·시간 제한.
- 복구: SQLite 트랜잭션, 작업 체크포인트, 비정상 종료 복구, 원격 게시 상태 조정.
- 성능: 기준 PC에서 설정 화면 2초 이내 응답 목표. 렌더 시간은 60초 영상으로 실측 후 예산 확정.
- 비용: 생성 전 예상 사용량 안내, 공급자가 제공하는 실제 사용량 기록, 예산 초과 시 신규 자동 생성 차단.
- 관측: 비밀값 제거된 진단 로그 내보내기, 작업별 오류 분류.
- 보관: 미디어 보관 기간·삭제 설정, 활성·예약 작업 자료는 자동 삭제 대상에서 제외.
- 백업: DB·설정·선택한 미디어 내보내기. 비밀키는 기본 백업에서 제외하고 복원 시 재연결 안내.

## 10. 개발 단계와 완료 기준

제품 Phase 1은 아래 0~5단계를 포함하는 수동 게시 MVP다. 제품 Phase 2는 예약·자동 게시 확장이다. 개발 단계 번호와 제품 Phase를 구분한다.

### 0단계 — 외부 연동·실행 가능성 검증

포트 80, 웹뷰 종료, FFmpeg 패키징, 네이버 조회, Meta 테스트 계정 릴스 게시, 실제 미디어 전송 경로를 검증한다. 사용 가능한 계정·키가 없으면 모의 연동으로 개발하되 실제 연동 완료라고 표시하지 않는다.

완료 기준: 실행/종료 실험 결과와 계정·권한·저장소 요구사항을 문서화하고 Windows·macOS의 CPU별 빌드 경로 확보.

### 1단계 — 로컬 앱과 설정

Launcher, FastAPI, React 화면, SQLite, 키 보관, 작업 목록 구현.

완료 기준: 실행파일에서 화면 표시, 포트 충돌 안내, 마지막 창 종료 후 포트 해제, 재실행 시 설정 보존.

### 2단계 — 수집과 카드 초안

네이버 검색, 수동 입력, 중복 처리, LLM 구조화 생성, 카드 편집 및 버전 관리 구현.

완료 기준: 후보를 선택해 출처가 연결된 카드 초안을 만들고 수정·저장 가능.

### 3단계 — 영상 제작

템플릿, 한글 레이아웃, 선택적 TTS, 자막, FFmpeg 렌더, MP4/PNG/SRT 내보내기 구현.

완료 기준: 실제 한글 5~7장 콘텐츠를 세로 영상으로 생성하고 자막·음성·줄바꿈을 시각·청각 검수.

### 4단계 — 수동 게시

계정 인증, 승인, 사용자 게시 버튼, 게시 파이프라인, 파일 내보내기, 실패 복구와 중복 방지 구현.

완료 기준: 테스트 계정에 릴스 1개 게시, 인증 만료·통신 단절·결과 미확인에서 중복 게시 방지 확인.

### 5단계 — 크로스플랫폼 배포와 매뉴얼

Windows·macOS 패키징과 깨끗한 환경에서의 검증, API 준비 매뉴얼과 사용 매뉴얼을 완료한다. 두 플랫폼에서 같은 기능을 제공하며 한쪽만 동작하면 Phase 1 완료로 보지 않는다.

완료 기준: Python/Node 미설치 Windows x64·macOS Apple Silicon·Intel 환경에서 설치·실행·제작·수동 게시·종료 성공. 매뉴얼에 실제 화면과 연결 테스트 결과 반영.

### Phase 2 — 예약·자동 운영

예약 게시, 소스 수집 주기, 자동 생성·게시 규칙, 일일 게시/비용 상한, 중단 버튼과 놓친 예약 처리 구현. 허가된 인기뉴스·블라인드 연동은 공급 경로 확보 상태에 따라 별도 확장한다.

완료 기준: 앱 실행 중 예약·자동 작업 성공, 앱 종료 시 중지, 재시작 시 놓친 예약 안내, 중복 게시 방지 확인.

일정은 0단계 검증 후 산정한다. Meta 앱 권한·검수 또는 콘텐츠 공급 계약의 대기 시간은 개발 일정과 분리한다.

## 11. MVP 인수 시나리오

1. Windows EXE와 macOS 앱 실행 시 기본 포트 80에서 관리 화면 표시; 충돌 시 안내 및 선택한 대체 포트 실행.
2. 마지막 창 종료 후 10초 안에 소유 서버·워커·FFmpeg 종료 및 포트 해제.
3. 계정과 API 키 저장·재시작·연결 테스트 성공; 화면·로그·DB에 비밀값 평문 노출 없음.
4. 네이버 검색에서 후보·출처·시각 조회, 동일 URL 중복 제거.
5. 제공 자료 기반 카드 수정 후 한글 영상·자막 생성; 텍스트 넘침과 오디오 싱크 검수.
6. 승인하지 않은 버전 게시 차단; 수정하면 기존 승인 무효화.
7. 지정 테스트 계정 게시 성공 및 게시 ID 기록.
8. 게시 요청 후 통신 단절 시 확인 필요 표시, 상태 조정 전 자동 중복 게시 없음.
9. 렌더 도중 종료·재실행 시 중단 상태 복구; 게시된 작업 자동 재게시 없음.
10. Phase 1에서 사용자가 게시 버튼을 누르지 않으면 외부 게시 없음; 예약·자동 게시 UI 없음.
11. 두 OS에서 동일 프로젝트 생성·편집·영상 내보내기·수동 게시 흐름 성공.
12. API 준비 및 사용 매뉴얼을 따라 첫 영상 제작·게시 가능. Phase 2에서 놓친 예약과 자동 운영을 별도 검증.

## 12. 확정할 사항

- 포트 80 사용 불가 시 대체 포트 허용 여부.
- 사용할 인스타그램 계정 수 및 프로페셔널 전환 여부.
- 우선 콘텐츠 분야, 말투, 브랜드 색상, 영상 샘플.
- LLM·TTS 공급자와 월 사용 예산.
- 실제 인기순위 필요 여부, 콘텐츠 사용 권한과 공급 경로.

확정 기준은 Windows·macOS 동시 지원, Phase 1 수동 게시·Phase 2 예약/자동 게시다. 나머지 제안 기본값은 대체 포트 선택 허용, 다계정 저장/작업당 단일 계정, 검토 후 게시, 네이버 검색·수동 입력 우선, 30~60초 한국어 릴스를 기준으로 구현을 준비한다.

## v0.2 일상 영상 스튜디오

콘텐츠 만들기 아래에 뉴스 카드뉴스와 일상 영상 메뉴를 분리했습니다. 공통 프로젝트 보관함에서 유형별로 필터할 수 있습니다. 디자인은 짙은 차콜 배경과 보라색 포인트를 사용하는 스튜디오 형태입니다.

일상 영상에서 JPEG·PNG·WebP 사진 1~10장을 올리고 순서를 정하세요. 큰 사진도 업로드 전에 긴 변 1920px 이하로 자동 축소·압축하며 HEIC는 JPEG로 변환한 뒤 추가하세요. 사진은 로컬에 저장하고 EXIF 위치 정보를 제거합니다. AI 자막 제안을 실행할 때만 축소한 사진과 작성한 설명을 OpenAI에 전송하며 API 비용이 발생합니다. 제안된 자막과 게시 문안은 수정할 수 있습니다.

장면 길이, 채우기/전체 보기, 사진 위치, 확대 효과, 전환, 자막 위치·스타일을 설정하세요. 음악은 분위기별 2~3곡을 추천하며, 사용자가 제공한 YouTube Audio Library 채널에서 확인하고 제작자 Incompetech에서 배포한 Kevin MacLeod CC BY 4.0 음악 8곡과 오리지널 CC0 연주곡 3곡을 제공합니다. 미리 듣고 선택하거나 음악 없이 만들 수 있습니다. CC BY 곡은 제목·저자·원본 링크·라이선스·편집 안내를 게시 문안과 함께 복사·공유하고 TXT로 내려받습니다. 음악 볼륨과 시작 위치를 조절할 수 있습니다. 추천은 앱에 포함된 곡을 사용하며 외부 실시간 음원 검색은 제공하지 않습니다. 플랫폼 자동 음원 판정 결과를 보장하지는 않습니다.

영상 만들기를 실행하면 1080×1920 MP4, SRT 자막, 장면 이미지 ZIP, 선택한 음악의 라이선스 안내를 내려받을 수 있습니다. 결과를 확인한 뒤 인스타그램에서 직접 올리거나, 연결된 계정으로 기존 수동 승인·게시 흐름을 사용하세요. 자동 예약 게시 기능은 Phase 2입니다. 사진 원본도 백업 ZIP에 포함되므로 백업을 안전하게 보관하세요.


## v0.3 모델 선택 · 테마 · 보안 정책

계정 · API 설정 하위 메뉴: AI 모델 설정, 뉴스 · 음성 API, 인스타그램 계정, 보안 · 로컬 저장, 백업 · 진단. AI 모델 설정에서 OpenAI, Claude, OpenAI 호환 API, 로컬 Ollama를 선택하고 모델 이름을 입력합니다. 제공자별 키는 OS 보안 저장소에 따로 저장하며 서로 공유하지 않습니다. 저장 후 생성 테스트는 소량 API 사용료가 발생할 수 있습니다. 콘텐츠 화면 상단에서 현재 모델을 확인하고 변경할 수 있습니다. 생성은 뉴스 초안/사진 자막을 만들며, 영상 합성은 로컬 FFmpeg가 수행합니다. 사진 기능은 이미지 입력을 지원하는 비전 모델이 필요합니다. 외부 API가 실패하면 다른 업체로 자동 전송하지 않고 기존 초안을 보존합니다.

Claude: https://platform.claude.com 에서 API 키·사용 가능 모델을 확인하세요. Messages API를 사용합니다. OpenAI 호환 서비스는 HTTPS 기본 주소(/v1 포함)와 해당 업체에서 발급받은 키·모델을 입력합니다. Chat Completions 및 JSON 객체 응답을 지원해야 합니다. OpenCode 같은 개발 도구 이름만으로 특정 API를 연결할 수는 없으므로 실제 제공자와 API 주소를 확인하세요. FreeLLM도 제공하는 API 형식·비전 모델 지원·약관을 확인해야 합니다.

로컬 Ollama: https://ollama.com 에서 OS에 맞게 설치하고 사용할 모델을 다운로드·실행합니다. 기본 API 주소는 http://127.0.0.1:11434/v1 입니다. 텍스트 모델은 뉴스 초안만, 비전 모델은 사진 자막까지 처리할 수 있습니다. 설치·모델 다운로드에는 인터넷이 필요하지만 앱의 로컬 모델 생성 요청은 localhost로만 보냅니다. 시스템 프록시와 HTTP 리디렉션도 사용하지 않습니다. 모델·서버 설치 및 실제 생성 호환성은 사용하는 환경에서 확인해야 합니다.

상단 라이트/다크 버튼으로 테마를 바꾸며 선택은 이 컴퓨터에 저장됩니다. 앱 테마는 출력 영상 템플릿을 바꾸지 않습니다.

보안 · 로컬 저장에서 정책을 선택합니다. 클라우드 AI 허용은 자료·축소 사진을 선택한 AI 업체에, 음성 텍스트를 OpenAI에, 뉴스 검색어를 네이버에 전송합니다. 공개 게시가 아니어도 업체 보관 정책이 적용됩니다. OpenAI 생성 요청에는 store:false를 사용하지만 이는 모든 업체 로그·보관을 없앤다는 뜻이 아닙니다. 외부 전송을 전혀 원하지 않으면 로컬 전용으로 바꾸고 Ollama 또는 직접 편집을 사용하세요. 이 모드는 외부 뉴스·음성·계정 API도 차단합니다.

이전 S3/인스타그램 직접 게시 기능과 달리 현재 기본 정책은 영상 외부 업로드 차단입니다. MP4를 로컬에 내려받아 사용자가 인스타그램에서 직접 게시합니다. API 키는 Keychain/Credential Manager에 저장되며 프로젝트·백업·진단에 포함되지 않습니다. API 키는 요청 인증을 위해 해당 발급 업체로 전달됩니다. 로컬 웹 서버는 127.0.0.1만 사용하고 세션·변경 요청 토큰을 검사하며, 외부 사이트 접근을 차단합니다. 백업은 사진·영상이 포함된 일반 ZIP이며 암호화되지 않으므로 파일 자체도 안전하게 보관하세요.
